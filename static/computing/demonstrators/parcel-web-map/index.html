What this page is: a static front-end demonstration of the parcel-screening workflow — parcels, overlays, popups, and client-side KML import. There is no server and no database behind it. The production version of this workflow would be backed by PostGIS (spatial queries, screening, and reporting in the database); this page is not a live PostGIS application.

Sources (accessed 2026-11-16): parcel boundaries — Volusia County GIS Open Data parcel layer (Florida public record, Fla. Stat. ch. 119); wetland indicator — USFWS National Wetlands Inventory, Oct 2026 release (doi:10.7944/usfws.nwi.202610); flood hazard — FEMA National Flood Hazard Layer, DFIRM 12127C, VERSION_ID 2.3.3.2. NWI and NFHL are mapped indicators, not a regulatory wetland delineation, jurisdictional determination, or flood determination; parcel boundaries are county polygons, not a surveyed boundary. This is a public-data method sample, not a client case study and not a client project.

Coverage note: wetland (NWI) coverage is 100% on all six parcels, so a 0% wetland overlap is a mapped result. Flood (NFHL) coverage is 100% on five parcels; on parcel 731503000001 it is 81.84% — 9,948.5 m² (18.16%) of that parcel lies outside the NFHL extract used here, so flood status there is unknown, not clear. Zone X is mapped flood-zone coverage, not flood hazard: only Zone A is Special Flood Hazard Area.

KML/KMZ privacy: imported files are parsed entirely in your browser (KML with toGeoJSON, KMZ unzipped with JSZip). Nothing is uploaded to any server.

Basemap: OpenStreetMap standard raster tiles (free, no API key). Aerial option: USGS The National Map orthoimagery (NAIP, U.S. public domain) — see Sources on the service page. Map library: MapLibre GL JS 4.7.1, vendored locally with toGeoJSON 5.8.1 and JSZip 3.10.1; no external scripts. An internet connection is needed for the tiles; the parcel data itself is embedded in this file.
